# Skill 开发教练

> **你手上有一个 Skill，但不确定它到底行不行；或者知道不行，却不知道从哪改起。**

先像医生一样给它**体检**，再像健身教练一样带它**升级**。
判据是同一套，只是用法不同：**边做边验、做完了回头验、验完再接着练**。
「从零做一个」也在里面——因为你得先知道合格长什么样，才判得出哪里不合格。

**装它**：[SkillHub](https://skillhub.cn/skills/indiv-zhunsheng/ian-skill-coach)（一键安装）

---

## 它解决的问题

多数讲 Skill 的资料在教「怎么写文档」。照着写完、装上去，然后就没有然后了——
**因为「写完」和「会被用」是两件事。**

Skill **不是文档，是给 Agent 的上下文包**，所以它要过的不是「人读得懂吗」，而是三个更硬的指标：

| 指标 | 不达标会怎样 |
|---|---|
| **会被触发吗** | 装了等于没装，**且没人知道** |
| **读得进去吗** | 关键约束被忽略，行为不稳定 |
| **每轮要付多少 token** | 装多了拖慢所有任务 |

这三条都不报错。这个技能把它们变成**可检查的判据**。

## 装到哪里

把它放到你的 Agent 工具的「技能目录」下，保持目录结构不变：

```
<技能目录>/
  ian-skill-coach/      ← 整个目录复制过去（目录名可自行改）
    SKILL.md
    references/
    scripts/
    tests/
```

常见位置（按你用的工具选一个）：

| 工具 | 常见技能目录 |
|---|---|
| Claude Code | `~/.claude/skills/` |
| WorkBuddy / CodeBuddy | `~/.workbuddy/skills/` |
| 其他 | 查你所用工具的文档 |

> ⚠️ **多数工具只在启动时扫描技能目录**——复制完之后**重启一次**，否则会以为没生效。

## 怎么用

### 直接说就行

装好之后，用日常说法触发即可：

- 「帮我做个 skill，我想要它……」
- 「这个需求该做 skill 还是 agent？」
- 「检查一下我这个 skill」「我的 skill 没人用，帮我看看」
- 「帮我理清需求」

### 手动跑检查器

```bash
# 诊断任意一个 skill（输出 A/B/C/D 结论等级）
python3 scripts/skillcoach.py --diagnose <skill目录>

# 检查自己（dogfooding）
python3 scripts/skillcoach.py --self

# 只算上下文成本（常驻 / 按需 / 深入各多少 token）
python3 scripts/skillcoach.py --cost <skill目录>

# 只跑触发门 / 只要安全扫描
python3 scripts/skillcoach.py --triggers <skill目录>
python3 scripts/skillcoach.py --security <skill目录>

# 需求澄清问卷
python3 scripts/skillcoach.py --intake

# 机器可读（stdout 是纯 JSON，可直接 json.loads）
python3 scripts/skillcoach.py --self --json
```

**退出码**：`0` 无 FAIL · `1` 有 FAIL · `2` 用法或路径错误。

**结论等级**：`A 工业级就绪` / `B 接近` / `C 有缺口` / `D 命中 Critical`。
Critical 单列为 **C1.2 负向边界 · I2 可验证 · I4 可维护 · I5 有边界** ——
它们失败不会立刻坏，只会**静默复利**，所以命中即 D。

### 跑回归测试

```bash
python3 tests/test_skillcoach.py
```

⚠️ **读最后一行**（`═══ 回归结论 ═══`）。用例内部会有诊断打印，用 `| tail` 容易看到中间的输出就以为过了。

## 它怎么带你做

**八道工序，实际是三段**——每道工序配一条判据，写完能自己跑脚本验：

| 段 | 工序 | 你在干什么 |
|---|---|---|
| **① 想清楚** | S0–S1 | 把需求说清（**说不清正是需要它的时候**）· 判断该做 Skill 还是 Agent · 看别人做到哪了 |
| **② 写出来** | S2–S3 | 起草 `SKILL.md` 与资源 · 把触发话术定下来 |
| **③ 验一遍** | S4–S8 | 对照验收 · 可移植 · 安全 · 打包 · 工业级就绪 |

> **S0 最不能跳。** 它会问你四件事，其中第四问「**这件事的成败卡在哪一环**」最容易漏——
> 如果答案是「讲得好 / 判断得准」，那**做出来也不解决你的问题**。这时候劝退比交付更负责。

完整操作见 `references/02-八道工序与四道门.md`。

---

## 诊断模式下，它给出什么

一份**按复利性排序**的诊断：

1. **结论等级**（A 工业级就绪 / B 接近 / C 有缺口 / D 命中 Critical）
2. **逐条判据打分 + 证据**——不是「感觉不好」，是「哪一条、在哪一行」
3. **说清什么时候会咬你**——这个缺陷在什么场景爆发
4. **给到具体动作**——改哪个文件、哪一段、改成什么

---

## 不适用

- **只判断一份交付物对不对** → 那是验收类技能的活
- **给 Skill 写推广文案、做传播** → 那是打磨传播类技能的活
- 一次性的临时提示词
- 与 Skill 无关的普通编码或写作任务

## 一条诚实说明

**这个技能承诺的是「我查过的都告诉你了」，不是「我保证它一定成」。**

四道门全过，你手上是「**没有已知缺陷**」，不是「保证好用」。
而且——**「没查」和「查过没问题」是两件事**：
前者标 `未检查`，**绝不标** `通过`。

完整判据与推理过程见 `references/01-上下文工程判据.md`。
